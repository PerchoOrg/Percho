# Percho · Vision Doc

> **Live there before you move there.**
> 让每个人在搬过去之前,先"住"进去。

---

## 1. 愿景 (Vision)

Percho 是一个以视频为核心的沉浸式生活体验平台。

我们相信,"住在哪里"是一个人一生中最重要的决定之一——它决定了你的通勤、你的邻居、孩子的学校、周末的样子,甚至你会成为什么样的人。但今天,人们做这个决定的方式仍然停留在上一个时代:刷房源列表、看户型图和精修照片、周末飞过去走马观花地看两天,然后凭感觉下注一个以年计的人生决策。

Percho 要改变这件事。我们用视频让用户足不出户地体验在不同国家、地区、城市、社区生活的真实感受——清晨的街道、傍晚的公园、周六的 farmers market、通勤路上的光线——并在这个过程中持续学习用户的偏好,帮助他们一步步 narrow down,最终找到想要长住或短租的生活片区,以及那套房子。

一句话:**从"看房"到"体验生活",从"搜索"到"被理解"。**

Percho 的名字来自 "perch"(栖息):鸟在落定之前,会飞过很多地方,停在高处看清全貌,再选择栖息之所。我们想成为每个人寻找栖息地时的那双翅膀和那个高处。

## 2. 问题 (The Problem)

**1. 用户购买的是生活方式,但平台售卖的是房源。**
Zillow、Redfin、Airbnb 都以"房源"为最小信息单位。可是没有人真的只是在买四面墙——他们在买一条街的安全感、一个社区的人群、一种周末的过法。现有产品的信息颗粒度与用户的真实决策颗粒度是错位的。

**2. 关键信息恰恰是列表里没有的。**
Listing 照片告诉你厨房长什么样,但不告诉你这条街晚上是什么氛围、邻居是什么样的人、离你在乎的生活半径有多远。这些信息今天只能靠实地踩点获得,而实地踩点对跨城、跨国用户几乎不可行。

**3. 搜索式交互要求用户"先知道自己要什么"。**
但绝大多数人只有模糊的感觉:"想安静一点""要有烟火气""离水近"。表单和筛选器无法承载这种偏好;它们需要被观察和推断,而不是被填写。

**4. 试错成本以年计。**
Relocation 搬错了城市、买错了社区,纠错周期是 1–5 年和一笔六位数的交易成本。这是消费决策里试错成本最高、而决策工具最原始的品类之一。

## 3. Why Now

- **视频已是信息消费的默认形态。** TikTok 训练了整整一代人用竖屏视频理解世界;"沉浸式短视频 + 兴趣推荐"的交互范式已被充分验证,只是还没有被认真地用在"居住决策"上。
- **AI 让"每个房源、每个社区都有一支片子"第一次在成本上可行。** MLS 数据接入 → AI 视频自动生成 → 自动分发,整条 pipeline 可以全自动运转。内容生产成本从"每条几百美元的人工拍摄"降到接近边际为零。
- **推荐系统成熟。** 偏好可以从滑动、停留、收藏等自然行为中学习和推断,无需问卷。
- **远程工作让居住第一次与工作地点解耦。** "住在哪里"从被动结果变成主动选择,催生了 relocation、数字游民、"先短租体验再定居"等全新决策场景。
- **NAR settlement 之后的结构性窗口。** 买方经纪佣金体系松动,buyer 在委托 agent 之前有了一段"自主探索期"——这正是 buyer-side 平台切入的时机。

## 4. 产品 (What We're Building)

### 核心体验
一个以全屏竖版视频为载体的沉浸式发现流——**but for places to live**。用户打开 Percho,不是在"找房",而是在"逛世界";系统在他们逛的过程中,弄清楚他们适合住在哪里。

具体的交互形态,我们刻意不在愿景层面写死——它会随验证持续演化。当前探索的方向是 **swipe card 模型**:feed 不是单一的内容流,而是多种卡片混排而成的一场"对话"——

- **内容卡(Listing / Community):** 承载沉浸式视频。右滑喜欢、左滑略过,长按预览,点入 Explore。
- **学习卡(Preference / Trade-off / Insight):** 用同一个滑动手势轻量地"问"。二选一揭示口味;trade-off 强制在两个维度间取舍,揭示优先级;Insight 卡呈现 AI 对用户的观察,用户可以同意或反驳——反驳本身就是高价值信号。
- **互动卡(Challenge):** 猜价格、市场小知识,让"逛"带有游戏感,也顺便完成 market education。

形态可以变,但两个不变量始终成立:**体验必须沉浸**(视频是隔着屏幕理解一个地方的最好媒介),**学习必须零摩擦**(所有偏好信号都来自同一个自然手势,永远不打断体验)。

### 三层内容结构(已在 prototype 中验证)
| 层级 | 内容 | 回答的问题 |
|---|---|---|
| **Home** | 房子本身 | 我会住在什么样的空间里? |
| **Street** | 街道与近邻 | 我每天出门看到的是什么? |
| **Community** | 社区、学校、商业、人群 | 我会过什么样的生活、和谁做邻居? |

用户在同一个物业上可以在三层之间无缝切换,像镜头拉远拉近一样理解一个"地点"。

### 四级地理漏斗
**国家 → 城市 → 社区 → 房子。**
用户可以从任意一层进入(有人从"想搬去葡萄牙"开始,有人从"这套房好看"开始),系统从行为信号中学习偏好,逐层收窄,最终收敛到具体的生活片区与具体的房源。

### 偏好引擎 (Preference Engine)
偏好信号来自两条通道,而且都发生在同一个滑动手势里:

- **被动信号:** 停留、回看、收藏、跳过——你总是停在有树荫的街道、跳过所有 high-rise、反复回看某个社区的黄昏;
- **主动信号:** 学习卡的轻量提问——二选一揭示口味,trade-off 揭示优先级(学区 vs 通勤,你选了哪边),对 Insight 卡的反驳则告诉引擎哪条推断错了、该降权哪些证据。

这些信号沉淀为 preference profile,驱动 feed 排序与最终的匹配清单。**问,但只用一次滑动的成本来问;学,但永远不发问卷。**

### Explore:从"心动"到"行动"的落点
每支视频都挂接结构化数据与真实供给:地图、学区、价格走势、社区数据,以及可直接触达的下一步——预约看房、预订短租。视频负责"感受",Explore 负责"决策"。

### 供给侧:自动化是根基
- **量产层:** MLS(FMLS / Georgia MLS,经 RESO Web API)→ ffmpeg Ken Burns 自动生成,覆盖全量房源
- **精品层:** AI 动效(Kling / Runway)用于 featured listings 与社区旗舰内容
- **补充层:** 本地创作者与居民的 UGC/PGC 社区内容,提供机器无法生成的"真实生活质感"

## 5. 用户与场景

1. **跨城 / 跨国 relocation 的购房者** —— 核心付费场景,决策金额最大、信息饥渴最强
2. **本地换房、但真正想换的是社区的家庭** —— "我知道我要搬,但不知道搬去哪个片区"
3. **数字游民与远程工作者** —— 选下一个 base,天然从短租切入
4. **渐进式决策者** —— 先短租体验一个社区几个月,再决定是否长住;Percho 是唯一把这两段旅程连成一条线的产品
5. **云体验用户** —— 暂时没有搬家计划、纯粹喜欢"逛别处生活"的人;他们是内容飞轮的燃料和未来的转化池

## 6. 差异化与护城河

**vs Zillow / Redfin:** 他们是房源数据库,我们是生活体验引擎。他们从搜索框开始,我们从感受开始;他们服务"已经知道自己要什么"的用户,我们服务决策链条更上游、心智尚未定型的用户。

**vs Airbnb:** 他们回答"这次旅行住哪",我们回答"我要不要住在这里"。短租在 Percho 里不是终点,而是长住决策的试住环节。

**vs YouTube / TikTok 上的城市 vlog:** 非结构化、不可检索、不可行动。Percho 的每支视频都绑定真实供给与结构化数据,看完可以直接走向决策。

**护城河的来源(按时间顺序建立):**
1. 自动化内容生产的**成本结构优势**(全自动 pipeline vs 人工拍摄)
2. 覆盖"地点"而非仅"房源"的**内容资产库**(社区/街道内容不随房源下架而失效,是可复用的长期资产)
3. 行为沉淀出的**偏好数据**——知道"什么样的人会爱上什么样的社区",这是任何房源数据库都没有的数据维度

## 7. 路线图 (Roadmap)

**Phase 1 — 打通闭环(Now · Atlanta)**
以 Atlanta 买房场景为切入(高库存、慢周转、buyer-friendly):MLS 自动视频 pipeline + 三层内容 feed 上线,验证核心假设——**视频沉浸 → 偏好学习 → 看房转化** 这条闭环真实成立。

**Phase 2 — Sun Belt 扩张 + 短租接入**
复制到 Orlando / Tampa / Jacksonville(共享 Stellar MLS,边际成本极低);接入短租供给,补全"先短租体验、再决定长住"的完整旅程,同时打开第二条收入线。

**Phase 3 — 快市场 v2 + 跨国体验图谱**
针对 Seattle 型快市场(低库存、拼速度)推出不同产品逻辑:社区频道、speed-to-publish、需求侧变现。同步扩展跨国内容(数字游民走廊:里斯本、清迈、墨西哥城……),从"美国买房工具"走向**全球生活体验图谱**——愿景的完整形态。

## 8. 商业模式(方向性)

- **Buyer-side 交易服务:** 高意图买家的转介绍与交易服务费(post-NAR 窗口的直接受益者)
- **短租预订佣金:** "试住"环节的自然变现
- **供给侧 SaaS:** 为 agent、开发商、短租运营者提供 AI 视频生成与分发工具
- **长期:** 基于偏好数据的高意图场景变现(mortgage、搬家、保险等居住决策链服务的导流)

原则:变现始终发生在**用户决策链的自然节点**上,而不是靠打断体验的广告。

---

## 9. North Star 与关键指标

**North Star:** 通过 Percho 完成的居住决策数(decisions made)——从"第一次刷到某个社区"到"预约看房 / 预订试住 / 签约"的完整旅程完成数。

**过程指标:**
- 沉浸时长与回访频率(体验是否成立)
- 偏好置信度增速(引擎是否在变聪明)
- 漏斗层级推进率:国家 → 城市 → 社区 → 房子(narrowing 是否真实发生)
- Feed → Explore 转化率(从感受到决策的桥是否通)
- 看房预约数 / 短租预订数(商业闭环)

## 10. 产品原则 (Principles)

1. **Experience over listings** —— 我们卖的是"住在那里的感受",房源只是载体
2. **Learn through swipes, never through forms** —— 每一次滑动都是偏好信号;可以轻量地问,但永远不打断体验、不让用户填表
3. **Automate the supply** —— 内容生产必须全自动,人力只投入在机器做不了的地方
4. **Every video is actionable** —— 每支视频都必须挂接真实供给与数据,拒绝"只能看不能动"的内容
5. **Start narrow, think global** —— 从 Atlanta 的一个漏斗做起,朝全球生活体验图谱去
